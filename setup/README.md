# Запуск платформы Solvery в self-hosted режиме

Краткая инструкция по настройке и развёртыванию платформы Solvery.space с помощью Docker. Режим self-hosted позволяет развернуть платформу на собственном сервере или VPS.

## 1. Перед началом

**Установленное ПО на целевой машине:**

| Среда                         | Что установить                                                |
| ----------------------------- | ------------------------------------------------------------- |
| Linux-сервер / VPS            | Docker Engine и Docker Compose (плагин или отдельная утилита) |
| Linux-десктоп, macOS, Windows | Docker Desktop (включает Compose)                             |

**Дополнительно понадобятся (сервисы и доступы):**

| Компонент                     | Назначение                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------ |
| **PostgreSQL** и **RabbitMQ** | Отдельные сервисы (контейнеры или хост) или добавленные в ваш `docker-compose` |
| **Identity Provider (OIDC)**  | Вход пользователей: URL discovery, client id и client secret                   |
| **SMTP-сервер**               | Отправка писем (регистрация, уведомления)                                      |
| **Домен и SSL-сертификаты**   | Для production за nginx (или аналогом)                                         |

После проверки окружения переходите к разделу [«Требования к системе»](#2-требования-к-системе).

## 2. Требования к системе

Минимальные ресурсы для запуска всех компонентов платформы (prime-api, prime-client, nginx, а также PostgreSQL и RabbitMQ при их размещении на том же хосте):

| Ресурс | Минимум   | Рекомендуется (production) |
| ------ | --------- | -------------------------- |
| RAM    | 4 GB      | 8 GB и более               |
| CPU    | 2 ядра    | 4 ядра и более             |
| Диск   | 50 GB SSD | 80 GB и более SSD          |

- Минимум подходит для **тестовых стендов и небольших нагрузок**.

После проверки ресурсов переходите к разделу [«Установка»](#3-установка).

## 3. Установка

Выполните шаги ниже в том порядке, в котором они приведены.

### 3.1. Получение конфигурации

Рядом с этим руководством в той же папке находятся все нужные конфигурации — их можно использовать для запуска платформы. Скопируйте содержимое папки в рабочую директорию развёртывания (или используйте её как рабочую).

**Файлы в комплекте:**

| Файл                                                | Назначение                                                 |
| --------------------------------------------------- | ---------------------------------------------------------- |
| `docker-compose.yml`                                | Описание сервисов и сетей                                  |
| `nginx/nginx.conf`                                  | Конфиг nginx (положите `nginx.conf` в подкаталог `nginx/`) |
| `prime-api.env.example`, `prime-client.env.example` | Шаблоны переменных окружения для следующих шагов           |

> **Важно.** Точные имена образов и теги версий (вместо плейсхолдеров `{customer}` и `{version}`) предоставляет техническая поддержка. Подставьте их в `docker-compose.yml` перед первым `docker compose pull`.

### 3.2. Структура каталогов

Создайте каталоги, которые монтируются в контейнеры согласно `docker-compose.yml`:

```bash
mkdir -p apps/prime-api apps/prime-api/logs apps/prime-api/static apps/prime-client nginx
```

При необходимости создайте каталог для SSL-сертификатов на хосте (например, `/etc/nginx/ssl`) — в примере nginx монтирует его в контейнер. Права доступа должны позволять чтение конфигурации nginx.

### 3.3. Файлы окружения

Создайте рабочие файлы `.env` из примеров:

```bash
cp prime-api.env.example apps/prime-api/.env
cp prime-client.env.example apps/prime-client/.env
```

Значения в этих файлах нужно будет задать в разделе [«Настройка и безопасность»](#4-настройка-и-безопасность). На этапе установки достаточно создать файлы.

> _Опционально._ Если prime-api подключается к сервисам по HTTPS с самоподписанными сертификатами, положите файл сертификата CA в `apps/prime-api/cert.pem` и укажите путь в `apps/prime-api/.env` как `NODE_EXTRA_CA_CERTS`.

### 3.4. Образы Docker

| Сервис       | Образ (шаблон)                                                                            |
| ------------ | ----------------------------------------------------------------------------------------- |
| prime-api    | `registry.solvery.space/platform-team/solvery-platform/{customer}/prime-api:{version}`    |
| prime-client | `registry.solvery.space/platform-team/solvery-platform/{customer}/prime-client:{version}` |

> **Доступ к registry закрытый.** Перед первым `docker compose pull` или `docker compose up` выполните авторизацию: `docker login registry.solvery.space`. Заранее предоставьте свой **IP-адрес** (или диапазон) для добавления в white-list — иначе запросы к registry будут отклоняться.
>
> Если образы забираются через прокси или кэш (Artifactory, Nexus и т.п.), настройте в нём авторизацию в наш registry и загрузку образов оттуда.

### 3.5. RabbitMQ и PostgreSQL

В поставляемом `docker-compose.yml` сервисы RabbitMQ и PostgreSQL не описаны. Их можно добавить в тот же compose или использовать внешние.

| Сервис         | Действие                                                                                                 | Переменная в `prime-api/.env` |
| -------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------- |
| **RabbitMQ**   | Добавить сервис в `docker-compose.yml` (пример фрагмента — у технической поддержки) или поднять отдельно | `MB_RABBITMQ_CONNECTION`      |
| **PostgreSQL** | Добавить сервис в `docker-compose.yml` или развернуть отдельно                                           | `DB_POSTGRESQL_CONNECTION`    |

> При добавлении RabbitMQ или PostgreSQL в compose добавьте у сервиса `prime-api` директиву `depends_on` на соответствующий сервис.

После выполнения шагов установки перейдите к разделу [«Настройка и безопасность»](#4-настройка-и-безопасность).

## 4. Настройка и безопасность

Перед первым запуском обязательно задайте все переменные, помеченные ниже как обязательные. Подробные комментарии — в файлах `prime-api.env.example` и `prime-client.env.example`.

### 4.1. Переменные окружения prime-api

Редактируйте файл **`apps/prime-api/.env`**.

**Обязательные переменные:**

| Категория                 | Переменные                                                                                                                   | Описание                                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **База данных**           | `DB_POSTGRESQL_CONNECTION`                                                                                                   | Строка подключения: `postgresql://user:password@host:port/database`. Надёжный пароль;                                                                                                  |
| **Очереди**               | `MB_RABBITMQ_CONNECTION`                                                                                                     | Строка подключения к RabbitMQ, например `amqp://user:password@host:5672`                                                                                                               |
| **Почта**                 | `SMTP_CONNECTION`, `SMTP_FROM_HEADER`                                                                                        | Подключение к SMTP (напр. `smtp://user:password@smtp.example.com:587`) и адрес отправителя (напр. `no-reply@yourdomain.com`). Для production — рабочий SMTP (AWS SES, SendGrid и т.п.) |
| **OIDC**                  | `OPENID_CONNECT_WELL_KNOWN_URL`, `OPENID_CONNECT_CLIENT_ID`, `OPENID_CONNECT_CLIENT_SECRET`, `OPENID_CONNECT_ID_TOKEN_SCOPE` | URL до `.well-known/openid-configuration` IdP, client id/secret, scope (напр. `openid profile email`). В IdP должен быть настроен redirect/callback URL вашего фронтенда               |
| **Секреты**               | `AUTHN_SECRET_ENCRYPTION_KEY`                                                                                                | Ключ для шифрования refresh-токенов в БД. Hex длиной в 32 символа: `openssl rand -hex 64`                                                                                              |
| **Администраторы**        | `PLATFORM_ADMIN_EMAIL`                                                                                                       | Один или несколько email через запятую — этим пользователям при инициализации назначаются права системного администратора                                                              |
| **Идентификация клиента** | `CUSTOMER_ID`                                                                                                                | Идентификатор клиента (значение сообщает техническая поддержка)                                                                                                                        |

**URL и CORS:**

| Переменная      | Назначение                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------- |
| `HOST`          | Базовый URL API (напр. `https://api.yourdomain.com`), без слеша в конце. Callback'и и ссылки в письмах.           |
| `FRONTEND_HOST` | URL фронтенда (напр. `https://yourdomain.com`). Если не задан — используется `HOST`. CORS и callback URL для OIDC |

_Опционально:_ `PORT`, `LOG_LEVEL`, пути логов, `IMAGE_STORAGE_PATH`, `FILE_STORAGE_TEMP_DIR`, `MULTIPART_MAX_FILE_SIZE`, настройки SMTP и сессий (`AUTHZ_*`), `OPENID_CONNECT_CACHE_TTL`, `OPENID_CONNECT_CONTENT_TYPE`. Описание — в `prime-api.env.example`

### 4.2. Переменные окружения prime-client

Редактируйте файл **`apps/prime-client/.env`**.

| Переменная     | Обязательно | Описание                                                                                                                                  |
| -------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `BACKEND_HOST` | да          | URL бэкенд API. При работе через nginx в одной Docker-сети укажите внутренний адрес, например `http://prime-api:3000`, без слеша в конце. |

Остальные переменные из примера при необходимости настраиваются по комментариям в `prime-client.env.example`.

### 4.3. Nginx: домен и SSL

В файле **`nginx/nginx.conf`** замените `example.com` на ваш домен (директивы `server_name` в блоках `server` для портов 80 и 443). Для production обязателен HTTPS.

| Что настроить   | Как                                                                                                                                                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Сертификаты** | В примере nginx ожидает `site.crt` и `site.key` в `/etc/nginx/ssl/` (том монтируется с хоста). Положите туда сертификаты (Let's Encrypt, внутренний CA и т.п.) и при необходимости обновите пути в конфиге. |
| **Ограничения** | При необходимости измените `client_max_body_size` (по умолчанию 150M) и списки `ssl_protocols` / `ssl_ciphers` под вашу политику безопасности.                                                              |

После сохранения изменений перезапустите nginx: `docker compose restart nginx`.

После настройки переходите к разделу [«Первый запуск и остановка»](#5-первый-запуск-и-остановка).

## 5. Первый запуск и остановка

> **Перед запуском проверьте:** заполнены обязательные переменные в `apps/prime-api/.env` и `apps/prime-client/.env`; в `nginx/nginx.conf` указан ваш домен; сертификаты лежат в каталоге, смонтированном в nginx (например, `/etc/nginx/ssl`); PostgreSQL и RabbitMQ доступны с хоста, где запускаются контейнеры.

**Основные команды:**

| Действие                       | Команда                                                               |
| ------------------------------ | --------------------------------------------------------------------- |
| Запуск всех сервисов           | `docker compose up -d` (выполнять из каталога с `docker-compose.yml`) |
| Проверка статуса               | `docker compose ps`                                                   |
| Просмотр логов (при проблемах) | `docker compose logs prime-api`                                       |
| Остановка                      | `docker compose down`                                                 |

После успешного подъёма переходите к разделу [«Запуск setup-scripts»](#6-запуск-setup-scripts).

## 6. Запуск setup-scripts

**Setup-scripts** — скрипты **одноразовой** преднастройки платформы. В отличие от миграций (схема БД) и сидов (идемпотентные данные при каждом старте), они выполняются **вручную и только один раз на окружение** и могут создавать бизнес-данные, настраивать программы через сервисы приложения. Повторный запуск **не идемпотентен** — скрипты запускают только через CLI.

> **Когда запускать:** после первого успешного подъёма платформы (миграции и сиды уже применены при старте prime-api). Один раз на окружение (dev, staging, production). При необходимости уточните у технической поддержки, какие скрипты предусмотрены для вашего клиента.

**Команда (внутри контейнера prime-api):**

```bash
docker compose exec prime-api pnpm tools setup
```

При успешном завершении в консоли появится сообщение о выполнении скриптов. После этого платформу можно использовать в штатном режиме. Переходите к разделу [«Обновление»](#7-обновление).

## 7. Обновление

> **Важно.** Перед обновлением обязательно сделайте бэкап базы данных. В случае сбоя миграций или отката вы сможете восстановить данные из резервной копии.

**Накат новой версии:** загрузите образы (`docker compose pull`), перезапустите контейнеры (`docker compose up -d` или `docker compose down` и затем `docker compose up -d`). Миграции БД выполняются при старте prime-api, отдельно их запускать не нужно.

**Откат версии** — вручную через CLI (тот же инструмент, что и для [запуска setup-scripts](#6-запуск-setup-scripts)).

| Действие                     | Команда                                                                                   |
| ---------------------------- | ----------------------------------------------------------------------------------------- |
| Откат до указанной версии    | `docker compose exec prime-api node dist/tools/cli.js migrate down --to-version <версия>` |
| Откат на одну миграцию назад | `docker compose exec prime-api node dist/tools/cli.js migrate down`                       |

> Перед откатом согласуйте действия с технической поддержкой платформы. Команды миграций предназначены для крайних случаев и при неправильном использовании могут привести к потере данных или несовместимости схемы.
